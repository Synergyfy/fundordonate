# 1.21 — FundOrDonate Visual Identity System

## Purpose
Define the visual design rules for FundOrDonate. This establishes the design language that all future UI implementation must follow. This is NOT the full frontend redesign — it is the foundation.

## Accessibility Requirements

1. **Colour contrast**: All text must meet WCAG AA (4.5:1 for normal text, 3:1 for large text)
2. **Focus indicators**: All interactive elements must have visible focus ring
3. **Touch targets**: Minimum 44x44px for mobile interactive elements
4. **Alt text**: All images must have descriptive alt text
5. **Semantic HTML**: Use proper heading hierarchy, landmarks, ARIA labels
6. **Keyboard navigation**: All functionality accessible via keyboard
7. **Screen reader**: Form labels, error messages, status updates must be announced

## Design Token Application

The existing Tailwind configuration (`apps/web/tailwind.config.js`) already defines:
- `primary` palette (blue scale)
- `secondary` palette (green scale)
- `fontFamily.sans` (Inter)

The existing `apps/web/src/index.css` defines:
- `.container-page` utility
- `.btn-primary`, `.btn-secondary`, `.btn-danger` button classes
- `.input-field` form control class
- `.label` form label class
- `.card` card class
- `.scrollbar-hide` utility

**No changes to existing files required.** This document establishes the rules; implementation follows in Phase 2+.
